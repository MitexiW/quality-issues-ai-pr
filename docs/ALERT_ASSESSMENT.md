# Model-assisted alert assessment and human validation

This procedure makes new judgments. It is not the frozen-data reproduction
command. Run from the repository root after installing `requirements-full.txt`.
Use a new output directory and keep credentials in environment variables.
Model calls cost money; human decisions cannot be regenerated by a script.

## 1. Prepare the alert batches

First complete [the CodeQL experiment](CODEQL_EXPERIMENT.md). The examples use
`outputs/codeql_experiment` as its directory. Keep its Git caches and recorded
before/head commits. Obtain PR/file metadata and the eligible PR roster:

```bash
python scripts/codeql/enrich_study_prs.py \
  --study-root outputs/codeql_experiment --require-token
python scripts/analyze_study_results.py \
  --study-root outputs/codeql_experiment \
  --output-dir outputs/codeql_experiment/reports/raw-analysis --mode final
python scripts/prepare_codeql_alert_adjudication.py \
  --analysis-pr-level outputs/codeql_experiment/reports/raw-analysis/analysis_pr_level.csv \
  --ai-alerts outputs/codeql_experiment/ai/results/introduced_alerts.csv \
  --human-alerts outputs/codeql_experiment/human/results/introduced_alerts.csv \
  --output-dir outputs/assessment/frame --alerts-per-batch 5 \
  --allow-unexpected-counts
```

Do not ignore a failed eligibility gate or treat failed scans as zero-alert PRs.
`--allow-unexpected-counts` permits a new frame size, not invalid input.
The frame contains `adjudication_alerts.csv`, `adjudication_prs.csv`, and
`adjudication_batches.csv`; batches contain at most five alerts from one PR.

For an **offline metadata test only**, substitute the released raw roster
`data/results/rq_analysis_final_20260727_v3/analysis_pr_level.csv` and
`data/inputs/raw_alerts/{ai,human}.csv`. Those sanitized alerts omit diagnostic
messages: use newly generated full alerts for a live assessment, not this test.

## 2. Check one batch, then explicitly enable model calls

Set `ASSESSMENT_BASE_URL` to your provider's Anthropic-compatible endpoint and
`ASSESSMENT_API_KEY` to its credential outside version control. The historical
requested model was `claude-opus-5[1m]`, with SDK 0.2.128 and bundled CLI 2.1.220;
see `config/study/model_screening_execution.json`. This is a recorded identifier,
not a promise that your provider serves that model. Record any substitution.

```bash
python scripts/run_codeql_alert_adjudication.py \
  --frame-dir outputs/assessment/frame --output-dir outputs/assessment/run \
  --ai-jobs outputs/codeql_experiment/ai/codeql_jobs.csv \
  --human-jobs outputs/codeql_experiment/human/codeql_jobs.csv \
  --ai-cache-dir outputs/codeql_experiment/ai/repos/.cache \
  --human-cache-dir outputs/codeql_experiment/human/repos/.cache \
  --provider compatible --base-url "$ASSESSMENT_BASE_URL" \
  --api-key-env ASSESSMENT_API_KEY --model 'claude-opus-5[1m]' \
  --effort max --max-turns 40 --max-budget-usd 10 --limit-batches 1
```

Without `--execute`, this runs preflight only. After checking the output, add
`--execute` to authorize calls; use `--resume` when continuing an existing run.
Remove `--limit-batches 1` only when ready to process the full frame. The budget
is per invocation/batch configuration, not a reliable provider-side total cap;
set a spending limit with the provider as well.

After all batches complete:

```bash
python scripts/summarize_codeql_alert_adjudication.py \
  --frame-dir outputs/assessment/frame --run-dir outputs/assessment/run \
  --output-dir outputs/assessment/summary
python scripts/prepare_human_review_queues.py \
  --input outputs/assessment/summary/model_adjudications.csv \
  --output-dir outputs/assessment/queues
```

The exporter rejects incomplete runs by default. `--allow-incomplete` is for
progress inspection only. The queue script retains an alert only when condition
presence, contextual validity and PR introduction are all `yes`; other completed
judgments go to the excluded queue. Neither queue is ground truth.

## 3. Review every alert in both queues

```bash
python scripts/manual_alert_review_app.py \
  --input outputs/assessment/queues/retained.csv \
  --output-dir outputs/assessment/human-retained \
  --ai-jobs outputs/codeql_experiment/ai/codeql_jobs.csv \
  --human-jobs outputs/codeql_experiment/human/codeql_jobs.csv \
  --ai-cache-dir outputs/codeql_experiment/ai/repos/.cache \
  --human-cache-dir outputs/codeql_experiment/human/repos/.cache
```

Open `http://127.0.0.1:20080` (forward that port through SSH/VS Code if needed).
Inspect before/head evidence and apply `config/study/manual_validation_schema.json`.
Finish and export the labels with the application's export button. Stop the app,
then repeat with `excluded.csv` and output directory `human-excluded`.
Skip a queue only if it has zero rows. Do not expose the app on a public interface.

Each directory preserves `review.sqlite3` and exported `human_labels.csv`.
Combine the two exports by column name, keeping exactly one completed final
label per input `alert_id`. Resolve deferred/conflicting judgments manually;
do not fill them from model judgments. Confirm that their union equals the full
frame before computing issue counts. Actionability is a separate field and is
not an extra condition for the three-property Quality outcome.

The released `build_validated_issue_snapshot.py` is a **historical snapshot
builder**: it enforces 7,124 alerts and an RQ2-ready roster. Do not force a new
experiment to those counts or silently reuse published labels. The new human
exports are the new experiment's outcomes; the existing frozen-data entry point
remains the route for reproducing the paper's exact statistics.
